# Systems Access

Which team works with which of the group's own systems, and what each may do. Group rules in [README.md](README.md) override anything here. System details are in [projects/](../projects/README.md).

## Access Map

| System | Business team (uses it, reports on it) | Software Studio (builds it) |
|---|---|---|
| [OSH-C Portal](../projects/osh-portal/SYSTEM.md) | Asbenz Desk: Personal Assistant, OSH Tracker | George and all engineering roles |
| [PRUBSN Agent Portal](../projects/agent-portal/SYSTEM.md) | Gabby, Client CRM, Compliance Reviewer | George and all engineering roles |
| [Merc Lab DMS](../projects/merclab-dms/SYSTEM.md) | Kazumi, COO, Customer CRM, CFO, Technical | George and all engineering roles |
| [Workshop Datahub](../projects/workshop-datahub/SYSTEM.md) | Kazumi, Technical | George and all engineering roles |

The Social Media teams do not use these systems and never take data from them.

## What Each Side May Do

| | Business team | Software Studio |
|---|---|---|
| Know what the system does and what comes next | Yes | Yes |
| Suggest features and report problems | Yes, through its CEO to George | Yes |
| Read the code and documents | No need | Yes |
| Change code | No | On a branch with a pull request, when the Chairman asks |
| Merge or release to the live app | No | Only after the Chairman approves |
| Use real customer, client or employer data | Inside the live app only | Never in development without the data owner's approval |

## Where the Teams See It

- **Command Center chat:** each CEO and team knows its own systems (what they do, status, next steps) and George's team knows all four.
- **George's studio briefing** (Wed and Sat) reports on each system from its repository.
- **Projects table** in the Command Center links each project to its repository.
