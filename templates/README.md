# Templates

Copy-ready templates for common documentation and process needs across every project. Copy the relevant template into your project (or its `docs/`/`templates/` subfolder) and fill it in — don't invent a new format for something already covered here.

| Template | Use When |
|---|---|
| [ADR_TEMPLATE.md](ADR_TEMPLATE.md) | Recording an architectural decision |
| [ARCHITECTURE_TEMPLATE.md](ARCHITECTURE_TEMPLATE.md) | Documenting a project's system design |
| [DATABASE_TEMPLATE.md](DATABASE_TEMPLATE.md) | Documenting a project's schema |
| [API_SPECIFICATION_TEMPLATE.md](API_SPECIFICATION_TEMPLATE.md) | Documenting an API endpoint |
| [PROJECT_README_TEMPLATE.md](PROJECT_README_TEMPLATE.md) | Starting a new project's README |
| [PROJECT_PROPOSAL_TEMPLATE.md](PROJECT_PROPOSAL_TEMPLATE.md) | Proposing an entirely new project |
| [FEATURE_PROPOSAL_TEMPLATE.md](FEATURE_PROPOSAL_TEMPLATE.md) | Proposing a feature within an existing project |
| [FEATURE_SPECIFICATION_TEMPLATE.md](FEATURE_SPECIFICATION_TEMPLATE.md) | Specifying exact behavior before implementation |
| [IMPLEMENTATION_PLAN_TEMPLATE.md](IMPLEMENTATION_PLAN_TEMPLATE.md) | Planning execution of an approved change |
| [IMPLEMENTATION_REPORT_TEMPLATE.md](IMPLEMENTATION_REPORT_TEMPLATE.md) | Summarizing completed work |
| [RISK_ASSESSMENT_TEMPLATE.md](RISK_ASSESSMENT_TEMPLATE.md) | Assessing risk before a significant change |
| [ROADMAP_TEMPLATE.md](ROADMAP_TEMPLATE.md) | Planning/tracking a project's roadmap |
| [TESTING_CHECKLIST_TEMPLATE.md](TESTING_CHECKLIST_TEMPLATE.md) | Verifying a change is adequately tested |
| [RELEASE_CHECKLIST_TEMPLATE.md](RELEASE_CHECKLIST_TEMPLATE.md) | Go/no-go decision before a release |
| [DEPLOYMENT_CHECKLIST_TEMPLATE.md](DEPLOYMENT_CHECKLIST_TEMPLATE.md) | Executing and verifying a deployment |
| [BUG_REPORT_TEMPLATE.md](BUG_REPORT_TEMPLATE.md) | Reporting a defect |
| [CHANGELOG_TEMPLATE.md](CHANGELOG_TEMPLATE.md) | Starting a project's CHANGELOG.md |
| [MEETING_NOTES_TEMPLATE.md](MEETING_NOTES_TEMPLATE.md) | Recording decisions made in a meeting |
| [DOCS_STRUCTURE_TEMPLATE.md](DOCS_STRUCTURE_TEMPLATE.md) | Reference content-skeletons for a project's own `docs/` folder |

## Adding a New Template

Only add a new template once an existing one has genuinely been copied and adapted for the same purpose more than once — otherwise it's premature abstraction. Match the header/section style of the closest existing template rather than inventing a new structure.
